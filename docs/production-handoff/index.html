常务会舆情报告完整处理流程

会议信息和监测数据进入后，依次完成数据准备、传播统计、观点发现、独立复核和报告生成。程序负责调度、计算、数据保存及渲染；AI承担语义判断；业务人员完成必要确认和最终核改。

输入：会议日期或议程＋监测系统导出文件；拟通过MCP补取的数据见统一取数表。

业务输出：Word报告、配套Excel和HTML工作台。来源依据及审核记录由后台留存。

调度：主流程与AI任务串行；独立复核使用新上下文。当前参考运行限45分钟，补充任务使用同一时钟余量。

验证边界：文件导入链路已有实测，MCP尚待接入验证；多人平台能力按生产要求建设。

当前范围：评论处理保留，暂不继续优化评论覆盖。具体期次的编辑确认集中见当前验证情况与业务确认。

处理流程与返回关系

补充任务复用S07—S11的阅读、选材与核验能力，只处理新增或未完成材料，不从S01重跑。所有补充共用原任务时钟；完整触发、停止和回退条件见E＋调度规则。

S06

AI判定条件
  • 相关性：正文实质讨论本期会议或政策，标题未出现“国常会”不单独否决。
  • 榜单适用性：排除纯营销引流或不适用的新闻拼盘。

→
输出审核后的公众号TOP10及原链接
节点细则：完整处理顺序、输出要求与异常

输入

公众号文章全文、阅读量/在看量、账号和时间。

处理顺序

  1. AI逐篇审核本期相关性与榜单适用性，保留每条决定。
  2. 程序按同账号/来源族去重，保留阅读量最高的一篇。
  3. 按阅读量降序，同档按在看/推荐量降序，再按原始行顺序取前10；100000+仅为封顶展示，不能推测真实阅读量。
  4. 不足10条继续审剩余候选；未审完整时显示排名不完整。

完整判定规则

  • 正文是否实质讨论本次会议或本期政策对象？正文相关可通过，不因标题没写“国常会”而排除。
  • 是不是广告、品牌引流或多条新闻拼盘？榜单只收可代表本期传播的相关文章，纯营销/早餐汇编排除并留理由。

执行与工具

AI读全文给逐篇决定；程序按账号/来源族保留最高阅读量文章，再排序取前10并生成链接。参考raw_system_workbook_pipeline.py的公众号审核与TOP构建逻辑。

通过条件

先筛再去重排序；有效来源充足时补足10个不同来源；阅读量缺失不补造。

输出

逐篇相关性审核表：文章ID、保留/排除/待核、理由；榜单：名次、标题、账号/来源族、日期、URL、原显示阅读量和排序依据；未审核范围。

失败与退回

只审了一部分候选，即使已列10条也不宣称是完整数据中的最终TOP10。正文观点不被这10篇限制。

  • Q2 增量：有没有主体自己的判断及理由、条件或建议？会议复述、法规条文和政策制定方阐释只作背景；新闻里真实第三方分析仍提取。
  • Q3 主体：谁提出判断？同文多名专家分别提取；同一人不同判断分别保存，不把转载账号当专家。
  • Q4 支持：连续原文能否支撑判断？保留对象、否定、草案阶段、预测语气和条件；明显单位/算术矛盾或论据不足的部分留待核。

执行与工具

程序建立全文队列、分批和原文定位；AI每批读完整文章并抽取候选。参考cwh_screen_bridge.py、fast_screen及cwh_raw_recall_collection.py。首批参考上限50篇、合计11万字符，不代表全库读尽；一篇补读文章同时提取相关议题，不逐题重复读。

通过条件

不截文章；批次超时不记已读；候选不是正式观点；新闻中嵌入专家分析仍可提名。

输出

逐篇阅读决定：文章ID、读完/排除/未完成、对应议题及理由；候选观点：原文ID、真实主体、身份原句、连续摘录、独立判断、条件/边界；未读清单。

程序先怎么筛、怎么排队

  1. 先记录规则剔除和重复关系。空正文、可确定的期外记录、完全重复或有明确包含依据的内容分别记原因；原始全文和代表关系仍留存。标题相似、账号名称或文章长短不能单独作为删除依据。
  2. 扫描完整正文中的分析线索。结合本期议题别名，查看附近是否有原因、机制、障碍、条件、建议或具名专业主体的发言。无本题线索、只剩通稿复述或通用套话等情况留规则处置记录；新闻中夹带的真实第三方分析仍需保留机会。这里是程序启发式，不是AI已判定文章无用。
  3. 按信息补足价值排序。考虑论证线索强度、尚未覆盖的判断、新主体、各议题覆盖及全文阅读成本。先安排各题的强线索文章，再给弱线索探索保留位置，最后用强线索补位；重复引文只影响排队，不证明整篇重复。
  4. 按完整文章装批。当前参考配置首批最多50篇、合计11万字符，其中弱线索探索最多12篇；每次AI阅读最多12篇、文章载荷6万字符，具体以选定模型配置为准。不截取文章来塞满队列，不按热度或原始表顺序直接取前50篇。
  5. 保存未读和误筛复查依据。队外备选仍未读，不直接判无观点；规则剔除另留审计。后续回捞优先处理备选库，不能据此宣称所有规则剔除均已重新审核或全量召回。规则参考conservative_filter.py、refined_filter.py、opinion_gate_v8.py及native_model_profiles.json。

调度规则、调用分工与回退条件

“薄弱”与补充停止条件如何判定

  1. 按核验后的正文计缺口。逐题对已独立核验并实际入文的“主体＋职务”去重计数；当前调度目标为6个，不足6个的题优先补充，数量更少的先处理。6是查找机会的调度目标，不是必须凑足的正文配额。
  2. 先利用已有提名，再决定是否新读。某题已有至少6个不同主体的合格提名尚未充分选用时，先重新选材，不为同一缺口重复读原文。仍需回捞时，从队外未读备选选文章，当前每题最多一小批、6篇／3.6万字符；按本题附近的建议、机制及实施线索排序，完整阅读全文。
  3. 按真实反馈继续搜。每个薄弱议题最多追加3轮、每轮4条查询；已读网页的具体剔除理由和未读清单分开交给AI。查询重复或不合格则不执行；搜索失败不改记零命中。实际轮数仍取决于原任务余量，不承诺每次全部用满。
  4. 保留出稿前的核验时间。回捞与搜索都受原研究截止约束，不能动用已留给编排、独立复核和出稿的时间。新增材料未核完或失败时，保留原核验稿及准确待审清单，不重置计时。
  5. 按当前参考实现决定是否替换。新包须通过独立核验，且已核验正文条数不少于原包，才替换原有效包；否则保留原核验稿，新增材料和回退理由另存。该数量保护不表示每一条旧观点必须原样保留，也不能替代观点质量判断。具体配置见execution_policy.v1.json中的automatic_remaining_research。
