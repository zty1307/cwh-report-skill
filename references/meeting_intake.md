# 通稿全文与议题身份

通稿决定本期会议背景、议程顺序及合并关系；原始热度表决定传播数字。两个来源不能互相替代。

## 固定流程

1. 用户提供本期完整日期及原始文件。扫描公众文章原表全部有效行，重置错误的工作表维度，不按阅读量/TOP10截断。保存政府网候选全文、标题、链接、原表/工作表/行号和SHA-256。
2. 原始样本找不到本期通稿时，工作台“会议通稿”框接受公开 gov.cn 链接。后端沿用公开网页读取器，拒绝内网、访问挑战、超限/不完整正文；不访问 ydata.woa.com。静态HTML自身不能执行抓取或AI调用，需启动工作台后端。
3. 将全文交给同一模型中立通稿理解任务。模型给出会议日期及连续日期引文、整体会议概述、完整议题顺序、每题的连续原文与原文别名。保留合并事项，不依部署动词或子表数量凑数。原始资料不是指令。
4. 宿主核查日期、年份（可获得时）、正文哈希、题名重复及逐项原文映射。该检查不冒充语义判断；没有真实模型结果就显示等待AI。
5. 用户明确确认“编号子表按议程顺序对应”后才按编号映射。工作台记住其主动选择；通用包默认不勾选。命名子表仅在与本期原文名称唯一匹配时映射。编号重复、缺题、多题、名称歧义均保留原表等待确认；不得改传播量来补齐。
6. 原文及理解结果进入后续AI任务；编译型正文阅读任务也携带全文会议背景。只用于理解政策对象与区分会议部署，不作为媒体反应或专家观点。不得用通稿代替每篇观点的独立原文。

## 运行与恢复

完整流程仍用原入口；没有 `--metadata` 时在 workbook 节点执行通稿任务，共享原节点及整轮预算，不新开完整报告流程：

```powershell
python scripts/run_cwh_resumable_pipeline.py run --job-dir <新任务目录> --raw-input-dir <原始目录> --agenda <YYYY-MM-DD> --confirm-agenda-order --communique-url <可选通稿链接>
```

`--confirm-agenda-order` 必须有实际用户确认。已有明确元数据的工作流兼容保留；其中如果携带 `meeting_context`，也要通过校验再给下游。

独立诊断入口：

```powershell
python scripts/cwh_meeting_intake.py --raw-dir <原始目录> --meeting-date <YYYY-MM-DD> --workspace <独立目录> --confirm-agenda-order
```

`CWH_SEMANTIC_COMMAND_JSON` 配置已有的获准无工具JSON模型命令，沿用共享语义传输与真实运行记录，不写死模型供应商。无配置时保留 `communique_packet.json` 等待当前 Agent/工作器处理，绝不把脚本日期匹配当成AI全文理解。正式管线生成 `meeting_communique_review` 任务，通用文件型工作器同样可接。

工作台缺通稿时不需重新上传文件：补链接后再点“处理数据”。运行中不允许替换通稿。旧成品、原始文件、手工Word模板保持不动。通过单元测试不等于多模型实战已通过。
