# Model-neutral execution contract

Bounded missing-evidence delivery now uses `deliver_available_with_gaps`: return usable evidence plus honest gaps, independently review existing claims and continue all output stages. Quantity targets must not stop Word/Excel/HTML delivery. The final audit may say `delivered_with_gaps` while preserving `ready_for_formal_delivery=false`; no claim of complete coverage is required for users to receive files. Source integrity and cross-output consistency still apply. Earlier references to missing-evidence blockers below describe hard access/structural failures, not a requirement to withhold all available content.

The default formal profile is `bounded_60m`, with a 3600-second limit and a 2700-second research cutoff that preserves delivery time. `bounded_40m` remains an explicit tighter option and `exhaustive` keeps uncapped research. These are engineering budgets, not evidence that every model can complete within them or permission to bypass a failed gate.

## Division of work

Scripts own input classification, workbook normalization, query generation, batching, deduplication, identifiers, time-window filtering, deterministic prose structure, rendering, hashing, retries and delivery status. A model may decide only relevance, speaker identity, atomic claims, stance, cluster assignment, semantic support and translation quality.

The model receives one bounded JSON task at a time. It writes final artifacts only to `declared_outputs` and collection seeds, raw responses or temporary batches only under `stage_workspace`. It must never edit the Skill, validators, `pipeline_state.json`, `pipeline_events.jsonl`, artifact hashes or report files. Missing evidence is a structured blocker, not an invitation to create a candidate or pad a paragraph. These contracts are instructions; the host must enforce filesystem permissions when sandboxing is required.

For a nonempty single-topic author response that omits at most 12 known IDs, the host may request only those full original records once, for at most 45 seconds within the original stage budget. Previously returned items, headings and clusters are locked; missing records are not automatically excluded. Empty author results, duplicate IDs, unknown IDs and an invalid completion remain structural failures. Missing reasons use topic-specific caches; one remaining-ID completion is allowed only inside the original combined 45-second reason budget. All native responses and completion runs are retained, and completed claims still undergo the same source and independent-support gates.

Raw public and overseas review transport defaults to 12 complete rows per batch. A host may explicitly set process-local `CWH_RAW_REVIEW_BATCH_SIZE` to an integer 1–12 for a slower provider. This changes neither source text nor evidence requirements, does not increase the stage budget, and may increase total latency; smaller batches are not a completion guarantee. Thinking/effort settings belong to the isolated host adapter, not model-specific Skill rules. A client accepting a setting does not establish that the provider honored it.

Word structural audit also checks unique native-approved domestic comment quotes against actual domestic Word paragraphs, not just JSON or appendix text. Invalid grouping must not hide an approval, and template-cap omissions are explicitly accounted for without changing original decisions. An explicit user domestic-section override is marked not applicable rather than falsely certified. This coverage check neither validates semantics nor substitutes for physical pagination/rendering inspection.

## Execution budgets

For `bounded_60m`, allocate time where each input mode actually performs the work. Raw normalization already includes public-article ranking review, overseas source/category review and hotword semantic selection; its later overseas and hotword stages still perform their required handoffs and bounded collection, without treating missing evidence as zero. Their shorter allocations do not waive source gates or authorize unreviewed material. Standard input retains the longer downstream research allocations.

| Stage seconds | Raw workbook | Standard workbook |
| --- | ---: | ---: |
| Workbook and raw semantic reviews | 1260 | 30 |
| Domestic authoring | 600 | 1290 |
| Independent claim verification | 300 | 600 |
| Overseas evidence handoff/collection | 60 | 240 |
| Hotword preparation | 30 | 90 |

Both modes keep domestic comments at 300, rendering at 180, final delivery checks at 120, and all other stage allocations identical. Each mode totals 2925 stage seconds plus the same 675-second reserve. The 2700-second research cutoff and 3600-second total stay unchanged; material shortages remain audited gaps, not invented evidence. The input-mode allocation is resolved once into the persisted contract and propagated to worker timeouts. Overrides cannot inflate the total or reduce independent review, rendering or final-gate allocations. This is an allocation, not a measured completion guarantee; reconfiguration of an existing diagnostic run must be disclosed, including its original wall-clock start.

The executable limits live in `config/execution_policy.v1.json`. Both bounded profiles use one active model worker and serial stages. Stage limits are not increased by the reserve. Research lanes are bounded by query, page-fetch and formal-voice limits. Monitoring-system full text is always processed first. Independent review is a separate sequential run. See `model_worker_host.md` for permission-aware transports and honest review-only delivery. Models do not need to run shell commands or edit pipeline state.

The 40-minute allocation is: preflight 30 seconds, intake 15, workbook 150, plan 30, domestic evidence 540, independent review 300, comments 330, overseas 270, hotwords 90, render 165 and final gate 120. Research retains ten query executions per topic so all source lanes, open search and a zero-new check can fit. It caps full-page fetches at 18 and named-entity expansions at two; comments allow four queries and 30 retained candidates; overseas allows one supplemental query and six page fetches. Both bounded profiles retain the same minimum independent voices, formal voice cap, source mapping and independent semantic review. A large raw workbook or limited access may exhaust these budgets and must produce an honest blocker.

The controller persists the first-run clock and the first-entry clock of each stage. Waiting for manual worker output and retrying consume the same budgets; explicit resume and invalidation do not grant a new time window. Each subprocess timeout is clipped to the remaining stage and job time. In-process stages are checked at return and cannot be accepted after expiry. Expiry records `time_budget_exhausted` and retains checkpoints; start a new job directory for a new timed evaluation. The 40-minute target requires actual end-to-end model tests, including network, collection, retries and delivery. Report completion rate and elapsed time together; an early timeout is not a speed improvement or a successful report.

The bounded profile stops after minimum lane coverage plus one evidenced zero-new round, or when the lane budget is exhausted. Additional relevant candidates remain in the audit as `formal_use=reserve`; they do not have to expand the formal report indefinitely. The optional `exhaustive` profile retains the older two-zero-round behavior and has no wall-clock SLA.

Large raw corpora are indexed once, with per-topic reading order and separate full-article files. In bounded mode each topic requires at least `min(12, corpus size)` real full-article reviews. The remaining source IDs can be explicitly deferred only against a hash-matching complete controller index. Deferred records are never labelled reviewed, excluded or evidence of zero new viewpoints; quality gates on selected claims remain unchanged. The controller can hydrate missing snapshots by `raw_evidence_record_id`, removing repeated multi-megabyte copying by the model. Exhaustive mode still requires every record to be reviewed.

The reading-order shortlist now retains up to 40 source-diversified articles without rejecting the remaining corpus. The compiled worker reads up to 20 original monitoring articles plus ten observed public-page URLs per topic in `bounded_60m`; `bounded_40m` reads up to 16 plus eight. Legacy plans keep 12 plus four. The initial fetch count is clipped to the profile page ceiling. Full text is not truncated, and all returned item IDs still require actual decisions; unread IDs remain deferred. Formal voices remain capped at 12 and all selected claims require independent review. Ten query slots now actually execute the planned academic/think-tank search and a supplementary public-platform search alongside the original media, industry, WeChat, Toutiao, Baijiahao and open-web lanes. These are discovery opportunities, not guaranteed independent viewpoints, and no topic-specific source, expert or baseline content is injected.

Bounded authoritative searches still confirm the meeting. Mainstream and industry searches target dated policy interpretation rather than requiring the full meeting name; public-platform tasks use their dated policy-impact query family instead of repeating the meeting-report query. Discovery-only subjects remove agenda wrappers such as hearing a progress report, preserving the policy names, planning periods, original topic labels and statistics. The same ten-slot ceiling applies. Within page-reading caps, different headlines receive priority over repeated normalized headlines; this is a reading-order hint, not semantic deduplication or an independent-voice certificate. All discovered URLs remain auditable. Discovery can therefore find a substantive policy article whose headline omits the meeting name, but final selection still requires original publication-time proof, full text, an independent judgment and a traceable relationship to the current agenda. A broader query never makes a generic health/law/industry article automatically eligible.

## Repair behavior

Available-with-gaps compiled work recovers locally from article timeouts, malformed native reading responses and exhausted reading budgets. Article calls may use up to 180 seconds within their assigned budget; remaining time is shared across topics instead of leaving only 45 seconds for each later topic. Original text stays intact. Unfinished articles remain explicitly deferred and are not semantic exclusions. The indexed corpus and exact deferred set remain mandatory; failing the reading quantity target is a recorded quality gap, not a delivery stopper.

If native grouping fails, the controller preserves existing extraction in source order under the original topic label, with no invented stance or semantic grouping. Claims beyond the existing voice cap remain explicitly mechanical reserves. All selected claims still enter independent review. That review uses full excerpts in batches, keeps successful native rows, and records timed-out or malformed rows as host-owned `uncertain`, never as a model verdict or approval. These rows are excluded from published prose through the audited retention path; only actual independently supported rows remain. Grouping and reading/review gaps prevent complete-coverage certification. Strict/exhaustive policies keep their blocking behavior. These recovery rules do not bypass permissions, source identity, source hashes or input validation.

For newly generated bounded plans, expanded reading counts are ceilings, not compulsory quotas. Before search, the compiled host freezes a per-topic allocation from the current stage time divided by topic count. At up to 360 planning seconds per topic it uses up to 12 complete monitoring articles plus four public-page fetches; between 360 and 660 seconds it grows linearly to the configured expanded ceilings. These are conservative workload-planning estimates, not measured latency guarantees. The 40-entry discovery shortlist, search lanes, original text, actual minimum raw coverage and independent verification stay unchanged. Unread corpus records remain deferred. The hash-bound allocation survives retries so later elapsed time cannot silently change accepted source scope. Legacy plans keep their original limits, and total clocks are never reset. Access-failure replacement still uses the original bounded recovery contract.

Validation feedback is machine-readable. A repair pass may change only the fields named by the validator and must preserve accepted identifiers and source snapshots. Each model stage receives at most two repair rounds per pipeline invocation in the bounded profile. A new explicit pipeline invocation rearms a previously failed stage but does not reset elapsed budgets; the operator does not edit attempts or hashes. Do not repeatedly resume an unchanged invalid output.

Budgeted page reading first allows one compact native discovery-priority call per topic, at most 30 seconds inside the same stage budget. It ranks only existing result IDs using titles and short discovery-snippet hints; those hints are not source evidence. This gives the model, rather than query order alone, a chance to prioritize interviews, analysis and editorials before the smaller full-page allocation. Original discoveries stay intact, selected pages must still be read in full and every formal claim independently verified. Timeout or malformed ranking falls back to the prior deterministic discovery order with the real failure recorded; permission and quota errors still propagate. Hash-bound ranking outcomes are reused on retry without falsely claiming a fresh judgment. No omitted page is labelled irrelevant or reviewed.

Web publication dates and publisher names still require literal original-text proof. A candidate failing this metadata gate gets one fresh local repair of at most 45 seconds within the existing stage deadline, not reuse of a rejected repair cache. If proof remains unavailable, quarantine only that candidate and continue the other claims and topics; no time left means quarantine without a model call. Preserve its original model decision and validation errors, never backfill a year or publisher, and do not call missing metadata proof an absence of interpretation. Any resulting count-based gap explanation is explicitly host-authored, not a model semantic certificate. Remaining claims still need the unchanged independent support and delivery gates.


The local metadata task receives only failing web IDs and their complete original text. Its reply may patch publisher and publication fields, not claims, speakers, roles, excerpts, headings or clusters; unaffected decisions remain byte-for-byte equivalent as objects. A completed but unparseable or contract-invalid local reply retains its actual run and quarantines only the originally failing candidates. Rate limits, authorization failures and other transport errors still propagate; host quarantine is not native semantic approval.

One intact initial JSON code fence with ordinary trailing explanation can be decoded without changing its JSON values. Competing blocks, a second structured answer, duplicate members and nonstandard constants are not eligible for this framing decoder. Declared report_agenda is carried for object disambiguation, never inferred as a source fact. The existing independent call also receives same-actor, same-source-hash overlapping original-span hints for cross-topic selections with different wording. These hints do not certify duplicates or delete evidence; the reviewer must distinguish the same judgment from genuinely different judgments and choose the directly corresponding topic where appropriate.

The latest event log is authoritative over a restored state snapshot. A state claiming an earlier run count or success after a later failed event is rejected as an integrity violation. Final success additionally requires every declared report and audit artifact to match its recorded hash.

Windows checkpoint replacement retries transient permission failures for at most 2.55 seconds of backoff. Persistent failures are surfaced with the old checkpoint intact. The model must never delete the target or patch its hash to clear a lock.

The subprocess watchdog runs separately from stdin/stdout communication. A Windows child that does not consume a large prompt cannot prevent timeout enforcement. Both monotonic and wall-clock deadlines are checked; a forward clock jump or resumed host does not grant more time. Cleanup targets only the child tree created for that invocation.

The host treats the final structured model event as authoritative even when a vendor CLI wrapper exits with shell code 0. A terminal rate-limit event or transient provider-network failure is normalized to a model-neutral `waiting_ai` checkpoint with any returned retry time; it does not consume semantic repair attempts or trigger immediate blind retries. Authentication, malformed output and semantic failures remain distinct hard failures. Raw review, compiled author/reviewer, comment, hotword and generic model adapters use the same transport classification.

`domestic_viewpoints` validates the unreviewed draft identically in automatic and manual-worker modes. Only the next stage requests independent semantic certification. That review worker may write its review packet; the controller alone writes the verified bundle and mapping audit. These are file contracts, not an operating-system sandbox; the host must scope worker permissions accordingly.

## Writing behavior

Raw public-account and overseas review use request-local short record aliases (`r1`, `r2`, ...). The host stores the exact alias map and restores original IDs before all source and coverage gates; no fuzzy matching, invented rows or coverage completion is permitted. Repairs use the same aliases, and checkpoints include the transport version. This prevents long-ID copying errors without certifying any semantic decision.

Article-reading-only requests omit the later topic-level `formal_selection` instructions. They still carry full original article bodies, agenda and evidence rules; the host retains the original packet for validation. Final cross-article selection happens separately and still receives its selection rules. Expert-attribution reading hints only borrow topic context from the same paragraph, not an adjacent background paragraph; this changes priority only, never source inclusion or semantic eligibility.

Reusable writing structure and sentence rules live in `config/formal_writing_rules.v1.json`. They were distilled from reviewed reports across unrelated subjects. They define chapter order, paragraph roles, stance headings, attribution forms, evidence density, comment grouping, hotword prose and overseas prose. No period-specific topic, person, source, number or conclusion is stored in the rules.

The model supplies atomic, evidence-backed judgments. Scripts assemble the fixed report skeleton. This keeps tone and structure stable across models while preserving the current meeting's evidence and uncertainty.

The compiled author may make one compact missing-reason completion call per topic (at most 45 seconds, 12 items and 32,000 request characters). Only already-returned dispositions with absent reasons are eligible; missing, duplicate or unknown IDs still fail exact coverage. For selected claims the host restores exact original excerpts rather than resending every full article. The completion model returns only IDs and reasons; existing claims, decisions, headings, source identities and spans cannot change. Original incomplete rows and the actual completion run are retained, and hash-checked identical requests can reuse their cache. This does not certify the original selection or bypass independent evidence verification.

The optional compiled transport presents original articles as numbered contiguous segments without deleting any characters. Models return an ordered segment-ID range; scripts extract verbatim text and exact offsets. This avoids copied or paraphrased quotations, but does not establish semantic support. Legacy free-text excerpts still require unique exact matches. Exact repetitions of the same identified subject's same claim are auditable duplicates; different substantive judgments by that subject remain separately traceable, even across clusters. Count the subject once, and never merge unreviewed meanings.

Draft structural completion fills only missing deterministic identifiers, source-text hashes and unique exact excerpt offsets. Existing nonempty values are preserved for validation, including invalid ones; ambiguous identity or repeated excerpts are not guessed. Frozen independently reviewed bundles are refused. The author must still supply consistent discovery/query references and actual source facts. No completion helper can establish semantic truth.

Word and Markdown use the same executable opening, chapter, attribution, numbering, comment and overseas frames. Explicit `meeting.chair_name` plus `meeting.chair_source` is required to name a chair. Source priority uses only supplied metadata. Unsupported rhetorical padding is rejected rather than silently deleted. Templates never supply a meeting-specific person, media placement or an unsupported majority claim.

For token economy, keep accepted artifacts on disk; read only current-stage inputs and required references, reuse source snapshots, and return structured changes instead of redrafting full prose. `scripts/cwh_timing_report.py --job-dir <job>` reports measured command duration separately from wait and other uninstrumented time. It is not an API token meter; old logs without instrumentation remain unknown.

The raw hotword transport pools overlapping or adjacent original source windows only when all source metadata matches and overlap text agrees exactly. Every term retains references to its original character intervals, and the host retains the unpooled packet for all source gates. No omitted gap is filled, no candidate or distinct-source count is dropped, and no semantic decision is supplied by the pool. `cwh_evidence_window_transport.reconstruct_term_windows` verifies exact round-trip preservation. This reduces repeated input text; it does not itself prove model quality or a faster end-to-end delivery.

In available-with-gaps raw review, packets above 48 candidates use topic-index partitions of at most 40 candidates. Candidates without a primary index use their existing first topic hit, or remain in an unassigned partition; none are silently dropped. Each native call retains exact source windows and all original topic numbering, and may add phrases supported by those windows. Added phrases have no invented frequency counts. A separate native global pass reads first-pass selections with their source evidence and performs cross-group deduplication and second review. Calls share the original stage deadline, with a 90-second per-call ceiling and time reserved for remaining calls. Successful model calls remain hash-cached, while original full-workbook hotword validation still decides support, count and delivery readiness. Batching changes transport, not evidence thresholds or the total clock.

An added hotword with no literal witness is quarantined locally in available-with-gaps mode, with its exact native selection, real run and missing-witness reason saved. It cannot enter the global selection or frequency count; other backed native terms still require the real global second pass. Empty selections, malformed fields and strict delivery continue to fail. A bad optional term must not prevent creation of the entire workbook and report.

Claim-ID grouping receives grouping and headline rules, not a request to certify absent full articles. Full-source reading and independent review still apply editorial eligibility. Independent review labels article openings as partial reference context and supplies verified absolute excerpt coordinates; sentence segmentation is not discontinuous quotation. A missing name in the opening cannot negate its presence in a later frozen excerpt. Local field/reference retries include only affected claims, retain their complete excerpts and preserve each original or retry reviewer's actual identity through retention.

Raw full-text discovery now preserves the existing shortlist and adds up to 24 analysis-title, 24 reasoning-hint and 16 corpus-spread candidates. These are generic reading hints, not source eligibility verdicts, account whitelists or baseline matches. Expanded rows retain complete original article files. Under the bounded reading-budget policy, one optional native call (at most 30 seconds within the existing deadline) selects the next full articles using short exact hints; invalid IDs or timeout keep the existing reading order, while permission errors remain explicit. Selected bodies still undergo full reading and independent review. The original full corpus, unread deferrals, top-reading appendix and its counts are unchanged.

`cwh_viewpoint_gate.py` applies the same density rule before and after rendering. It counts distinct speaker identities and Chinese characters, not URL count or attribution verbs. Accepted `thin_cluster_exception` records appear in `cwh_audit.json` under `quality_summary.viewpoint_density_exceptions`. An exception never authorizes missing source evidence or unsupported claims.

### One-topic requests and effective worker budgets

In available-with-gaps bounded delivery, reaching the configured per-topic unique executed query cap may end research without proving saturation. The controller derives `budget_stop` from saved query IDs, concrete queries, execution timestamps, backends and result snapshots, checked against the installed profile limit. It preserves positive `new_independent_viewpoints` counts and marks `completed=false`, never inventing a zero-new round. This exception requires bounded mode and the available-delivery policy; exhaustive, strict, unexecuted, duplicated and incomplete query records still fail. Route coverage, source mapping, full-text reading and independent semantic verification remain mandatory. The unfinished search is carried into synchronized audit gaps and prevents formal-ready certification.

Both bounded profiles expose a 180-second maximum for one topic's author call and a 45-second reservation per future topic, reduced proportionally when remaining time is short. These are model-neutral request limits, not a per-topic completion promise or permission to mark unread material reviewed. Completed responses remain hash-cached; a failed call keeps the real source packet and is retried only through the controller. Exhaustive retains the existing uncapped request allocation.

The outer AI-worker timeout and task.remaining_budget_seconds must use the same runner-calculated effective budget, already constrained by stage elapsed time, predecessor carry, research cutoff and global clock. Do not hand a worker a larger carried allocation but kill it at the original nominal stage limit. Request limits never enlarge the effective allocation, change saved start times, borrow later delivery budgets or certify a failed test.

Raw overseas review packets above 12 rows are reviewed in sequential batches of at most 12 complete original rows. Each call is bounded by the remaining effective budget and 180 seconds. Every batch must return every input ID exactly once, including exclusions; the host resolves excerpts against that batch and remaps range IDs to the full packet. Hash-checked completed batches survive later format failures and are reused on a checkpoint retry, not marked successful by missing rows. Factual summaries remain empty to avoid repeating facts in long JSON. Classification, source body, row coverage and final aggregate reconciliation are unchanged; batching is not a guarantee that any model will succeed within one hour.

Public-account TOP review uses the same complete-row batches and hash checkpoints. If source-family deduplication leaves fewer than TOP N, the host expands the ranked candidate prefix by 30 real rows, up to 90 candidates (or the original tied-ceiling batch, if larger). It does not send the same insufficient packet repeatedly. Previously unchanged full batches are reused; an enlarged last batch is reviewed again. If candidates are exhausted or the fixed cap is reached, reviewed results remain exportable with explicit evidence_shortfall and raw formal readiness remains false. This is a bounded reviewed ranking, not a claim that all remaining lower-ranked rows were read or that TOP N is complete.

The configured public_roundup_patterns are fixed appendix exclusions, not suggestions that a model may override merely because the meeting leads one bulletin. The host keeps model_decision and model_review_reason alongside host_fixed_rule_veto and the final exclusion. It does not report its deterministic exclusion as a new AI semantic judgment. This appendix rule does not delete the independent full-article viewpoint evidence pool.

Raw article reading hints recognize explicitly named professional attribution, including "X told an outlet" and "X said in an interview", and later mentions of that same explicitly introduced person in the same source near current topic aliases. Hints only sort the bounded reading list; they cannot certify a person's role, a quote, policy relevance or eligibility, and do not remove deferred source records. Do not treat an increased hint count or a promoted article as an additional accepted voice.

Named-person mapping must not split a two-to-four-character Chinese name merely because it contains 和 or 及. Explicit punctuation lists and longer connective-separated lists of complete names remain rejected. This structural check is not a person-identity certificate: the original-name, role, excerpt and independent semantic checks still apply. Never ask a model to rename a real person to bypass a false separator match.

If a genuine-comment reviewer supplies a shared topic heading but omits the individual heading, the host may reuse that explicit heading only when this topic has exactly one formally selected included comment. It preserves the original model output and logs transport_heading_completions. Multiple selected comments, missing shared headings, excluded rows and nonempty individual headings are not guessed or overwritten; comment text, routing, labels and formal-selection decisions are unchanged.
### Missing web bodies are a controller fact, not a semantic verdict

The compiled author transport sends only web rows with an obtained non-whitespace body (raw monitoring rows retain their existing review path). Web discoveries without a body are reattached by exact original ID as `deterministic_body_availability_gate`, with no selected claims and an explicit not-read / pending-body reason. They remain in query and candidate audits as `discovery_metadata_only` and `machine_disposition`, not `model_disposition` or completed full-text semantic review. Readable source text, IDs, discovery records and URLs are preserved; lack of a body does not establish irrelevance or absence of interpretation. A model may not return reviews for IDs it was not supplied. A topic containing only unread web discoveries needs no model call and carries an explicit evidence shortfall.
